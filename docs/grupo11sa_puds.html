1.- Perfil

1.1.- Introducción

En la gestión universitaria moderna, el seguimiento oportuno de los entornos virtuales de aprendizaje resulta fundamental para garantizar la calidad académica y prevenir la deserción estudiantil. La Dirección de Educación a Distancia y Tecnología Educativa (DEDTE) de la Universidad Autónoma Gabriel René Moreno (UAGRM) administra múltiples instancias de Moodle 5.1 (Virtual, Apoyo Presencial y Capacitación Docente) que atienden a miles de estudiantes cada semestre.

El presente documento describe el diseño, desarrollo y despliegue del sistema DEDTE Mail Analytics (Grupo #11 SA), una plataforma backend descentralizada basada en una Arquitectura Email-Driven. Los usuarios interactúan con la base de datos relacional PostgreSQL enviando comandos estructurados bajo la gramática COMANDO["param1","param2",...] en el Asunto (Subject) de sus correos electrónicos hacia grupo11sa@tecnoweb.org.bo, recibiendo respuestas automáticas en formato HTML.

El sistema fue desarrollado en Java 17 con empaquetado Maven y desplegado en producción sobre un servidor VPS Linux Ubuntu 24.04 LTS en Microsoft Azure (IP fija 57.156.60.79, región chilecentral), implementando directamente los protocolos POP3 y SMTP sobre sockets TCP/IP y utilizando consultas preparadas (Prepared Statements) contra PostgreSQL.

1.2.- Antecedentes

Actualmente el monitoreo de apertura de aulas virtuales, matrícula, densidad estudiantil, retiros, moras y rendimiento académico se consolida de manera fragmentada mediante reportes manuales en hojas de cálculo (Excel/ODS) extraídos de cada entorno Moodle. En el marco de la materia INF513 – Tecnología Web, el Proyecto #1 resuelve esta necesidad mediante un canal universal y liviano (correo electrónico) y construye el esquema de base de datos PostgreSQL que será reutilizado directamente en el Proyecto #2 (Sistema Web de 3 Capas).

1.3.- Justificación

  • Justificación Técnica: Implementa comunicación de bajo nivel con servidores de correo mediante sockets TCP/IP (POP3 puerto 110 y SMTP puerto 25), decodificación MIME UTF-8, análisis léxico-sintáctico con soporte de comillas escapadas ("), prevención de inyección SQL mediante Prepared Statements y auditoría persistente en access.log y error.log.
  • Justificación Académica: Aplica integralmente el Proceso Unificado de Desarrollo de Software (PUDS), modelado UML, arquitectura en capas, concurrencia mediante hilos y despliegue real en un servidor Linux en la nube.
  • Justificación Práctica: Permite a directivos, analistas y docentes del DEDTE consultar indicadores clave (KPIs), registrar cortes de rendimiento y evaluar semáforos de deserción desde cualquier dispositivo con correo electrónico sin requerir software adicional.

1.4.- Descripción del Problema

  • Fragmentación de Entornos Moodle: Múltiples instancias (Virtual, Presencial y Capacitación) sin monitoreo unificado de estado y versión.
  • Control manual de apertura e infraestructura: Dificultad para auditar rápidamente qué aulas por facultad, carrera, sigla y grupo se encuentran aperturadas, observadas o pendientes.
  • Detección tardía de deserción académica: Falta de cálculo automatizado de tasas de deserción (retiros y moras) y clasificación de riesgo por semáforos (VERDE, AMARILLO, ROJO).
  • Ausencia de comparativas históricas inmediatas: Limitación para contrastar indicadores de aprobación y deserción entre gestiones semestrales (ej. 2025-2 vs 2026-2).

2.- Marco Teórico y Descripción de la Institución

2.1.- Correo Electrónico y Protocolos

  • Origen y Funcionamiento: Desde 1971 (Ray Tomlinson / ARPANET), el correo electrónico opera bajo el modelo cliente-servidor de forma asíncrona, permitiendo interoperabilidad universal.
  • Protocolo SMTP (RFC 5321 — Puerto 25): Transfiere correos salientes mediante comandos textuales HELO, MAIL FROM, RCPT TO, DATA (con dot-stuffing) y QUIT.
  • Protocolo POP3 (RFC 1939 — Puerto 110): Recupera correos entrantes del buzón mediante USER, PASS, STAT, RETR, DELE y QUIT.
  • MIME (RFC 2045): Extiende el correo para soportar contenido HTML UTF-8 y decodificación de asuntos en Base64 / Quoted-Printable (tildes y letra ñ).
  • Sockets TCP/IP: Permiten establecer conexiones orientadas a flujo confiables para implementar POP3 y SMTP manualmente con delimitadores .

2.2.- Descripción de la Institución: DEDTE – UAGRM

La Dirección de Educación a Distancia y Tecnología Educativa (DEDTE) de la UAGRM impulsa la educación virtual y el apoyo tecnológico a las carreras presenciales mediante el ecosistema AVA (ava.uagrm.edu.bo) sobre Moodle 5.1.

  • Misión: Administrar, innovar y monitorear los entornos virtuales de aprendizaje de la UAGRM asegurando continuidad académica y formación docente de calidad.
  • Visión: Consolidar un ecosistema digital universitario basado en datos en tiempo real que reduzca la deserción y eleve el rendimiento académico.
  • Valores: Transparencia, rigor académico, innovación tecnológica, accesibilidad y mejora continua.

7.1.- Script DDL PostgreSQL (sql/01_schema_dedte.sql)

-- =============================================================================
-- UAGRM - FICCT - INF513 Tecnología Web (Gestión 2026-2)
-- Grupo #11 SA: Duran Marcelo Kelly Alisson / Quispe Delgado Julio Cesar
-- Sistema de Analítica y Monitoreo Académico DEDTE (Entornos Moodle AVA)
-- Motor: PostgreSQL (Compatible con Proyecto 1 Mail y Proyecto 2 Web)
-- =============================================================================

-- Limpieza controlada (solo para inicialización limpia)
DROP TABLE IF EXISTS evaluacion_riesgo CASCADE;
DROP TABLE IF EXISTS monitoreo_academico CASCADE;
DROP TABLE IF EXISTS aulas_apertura CASCADE;
DROP TABLE IF EXISTS historicos_semestrales CASCADE;
DROP TABLE IF EXISTS entornos_moodle CASCADE;
DROP TABLE IF EXISTS parametros_sistema CASCADE;
DROP TABLE IF EXISTS usuarios CASCADE;

-- =============================================================================
-- CU1: Gestión de Administración del Sistema (Usuarios y Parámetros)
-- =============================================================================
CREATE TABLE usuarios (
    id              SERIAL PRIMARY KEY,
    ci              VARCHAR(20) NOT NULL UNIQUE,
    nombre          VARCHAR(100) NOT NULL,
    apellido        VARCHAR(100) NOT NULL,
    rol             VARCHAR(30) NOT NULL CHECK (rol IN ('ADMIN', 'DIRECTIVO', 'ANALISTA', 'DOCENTE')),
    email           VARCHAR(120) NOT NULL UNIQUE,
    telefono        VARCHAR(30),
    estado          VARCHAR(15) NOT NULL DEFAULT 'ACTIVO' CHECK (estado IN ('ACTIVO', 'INACTIVO')),
    created_at      TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE parametros_sistema (
    id              SERIAL PRIMARY KEY,
    clave           VARCHAR(60) NOT NULL UNIQUE,
    valor           VARCHAR(120) NOT NULL,
    descripcion     VARCHAR(255) NOT NULL,
    updated_at      TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- =============================================================================
-- CU2: Gestión de Conexión de Entornos Moodle (Virtual, Presencial, Capacitación)
-- =============================================================================
CREATE TABLE entornos_moodle (
    id              SERIAL PRIMARY KEY,
    codigo          VARCHAR(20) NOT NULL UNIQUE,
    nombre          VARCHAR(100) NOT NULL,
    tipo            VARCHAR(20) NOT NULL CHECK (tipo IN ('VIRTUAL', 'PRESENCIAL', 'CAPACITACION')),
    url_base        VARCHAR(200) NOT NULL,
    version_moodle  VARCHAR(20) NOT NULL DEFAULT '5.1',
    estado_conexion VARCHAR(20) NOT NULL DEFAULT 'ACTIVO' CHECK (estado_conexion IN ('ACTIVO', 'INACTIVO', 'MANTENIMIENTO')),
    ultima_sinc     TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- =============================================================================
-- CU3: Gestión de Automatizar Reporte de Apertura e Infraestructura
-- =============================================================================
CREATE TABLE aulas_apertura (
    id                  SERIAL PRIMARY KEY,
    entorno_id          INT NOT NULL REFERENCES entornos_moodle(id) ON DELETE RESTRICT,
    gestion             VARCHAR(15) NOT NULL,
    facultad            VARCHAR(100) NOT NULL,
    carrera             VARCHAR(120) NOT NULL,
    sigla               VARCHAR(20) NOT NULL,
    grupo               VARCHAR(10) NOT NULL,
    materia             VARCHAR(150) NOT NULL,
    docente_codigo      VARCHAR(30) NOT NULL,
    docente_nombre      VARCHAR(150) NOT NULL,
    formato_curso       VARCHAR(40) NOT NULL DEFAULT 'MOSAICOS',
    estado_apertura     VARCHAR(25) NOT NULL DEFAULT 'APERTURADA'
                        CHECK (estado_apertura IN ('APERTURADA', 'PENDIENTE', 'OBSERVADA', 'CERRADA')),
    fecha_apertura      DATE NOT NULL DEFAULT CURRENT_DATE,
    UNIQUE (entorno_id, gestion, sigla, grupo)
);

-- =============================================================================
-- CU4: Gestión de Monitoreo Matrícula, Densidad Estudiantil y Rendimiento
-- =============================================================================
CREATE TABLE monitoreo_academico (
    id                  SERIAL PRIMARY KEY,
    aula_id             INT NOT NULL REFERENCES aulas_apertura(id) ON DELETE CASCADE,
    inscritos           INT NOT NULL CHECK (inscritos >= 0),
    activos             INT NOT NULL CHECK (activos >= 0),
    aprobados           INT NOT NULL DEFAULT 0 CHECK (aprobados >= 0),
    reprobados          INT NOT NULL DEFAULT 0 CHECK (reprobados >= 0),
    promedio_notas      NUMERIC(5,2) NOT NULL DEFAULT 0.00 CHECK (promedio_notas >= 0 AND promedio_notas <= 100),
    densidad_pct        NUMERIC(5,2) NOT NULL DEFAULT 0.00,
    fecha_corte         DATE NOT NULL DEFAULT CURRENT_DATE
);

-- =============================================================================
-- CU5: Gestión de Evaluar Deserción y Asignar Semáforos de Riesgo Académico
-- =============================================================================
CREATE TABLE evaluacion_riesgo (
    id                  SERIAL PRIMARY KEY,
    aula_id             INT NOT NULL REFERENCES aulas_apertura(id) ON DELETE CASCADE,
    total_inscritos     INT NOT NULL CHECK (total_inscritos > 0),
    retiros             INT NOT NULL DEFAULT 0 CHECK (retiros >= 0),
    en_mora             INT NOT NULL DEFAULT 0 CHECK (en_mora >= 0),
    tasa_desercion      NUMERIC(5,2) NOT NULL DEFAULT 0.00,
    semaforo            VARCHAR(10) NOT NULL CHECK (semaforo IN ('VERDE', 'AMARILLO', 'ROJO')),
    observacion         VARCHAR(255),
    fecha_evaluacion    DATE NOT NULL DEFAULT CURRENT_DATE
);

-- =============================================================================
-- CU7: Gestión de Consultar Históricos Semestrales
-- =============================================================================
CREATE TABLE historicos_semestrales (
    id                  SERIAL PRIMARY KEY,
    gestion             VARCHAR(15) NOT NULL,
    entorno_id          INT NOT NULL REFERENCES entornos_moodle(id) ON DELETE RESTRICT,
    facultad            VARCHAR(100) NOT NULL,
    total_aulas         INT NOT NULL CHECK (total_aulas >= 0),
    total_inscritos     INT NOT NULL CHECK (total_inscritos >= 0),
    tasa_aprobacion     NUMERIC(5,2) NOT NULL CHECK (tasa_aprobacion >= 0 AND tasa_aprobacion <= 100),
    tasa_desercion      NUMERIC(5,2) NOT NULL CHECK (tasa_desercion >= 0 AND tasa_desercion <= 100),
    promedio_general    NUMERIC(5,2) NOT NULL CHECK (promedio_general >= 0 AND promedio_general <= 100),
    UNIQUE (gestion, entorno_id, facultad)
);

-- Índices para consultas rápidas (CU6 Dashboard y CU8 Reportes)
CREATE INDEX idx_aulas_gestion ON aulas_apertura(gestion);
CREATE INDEX idx_aulas_facultad ON aulas_apertura(facultad);
CREATE INDEX idx_riesgo_semaforo ON evaluacion_riesgo(semaforo);
CREATE INDEX idx_hist_gestion ON historicos_semestrales(gestion);

8.- Conclusión

El desarrollo del sistema DEDTE Mail Analytics (Grupo #11 SA) demostró la viabilidad técnica de operar una plataforma completa de monitoreo y analítica universitaria exclusivamente a través del correo electrónico:

  • OE1: Se analizaron los procesos académicos del DEDTE-UAGRM y se formalizaron los 8 casos de uso aprobados.
  • OE2: Se estructuró una base de datos PostgreSQL de 7 tablas normalizadas lista para ser compartida con el Proyecto #2 (Sistema Web).
  • OE3: Se construyó un analizador léxico estricto para COMANDO["p1","p2"] con soporte UTF-8 y comillas escapadas, respaldado por Prepared Statements.
  • OE4: Se implementaron sockets TCP/IP puros para POP3 y SMTP, respuestas HTML institucionales y registros de auditoría access.log / error.log.
  • OE5: El sistema fue desplegado y validado integralmente en un VPS Linux Ubuntu 24.04 en Microsoft Azure (57.156.60.79).

9.- Recomendaciones

  1. Configurar un servicio systemd en el VPS Azure para reinicio automático ante eventuales reinicios del servidor.
  2. Reutilizar directamente las 7 tablas de db_grupo11sa en el Proyecto #2 (Laravel + React) añadiendo control de acceso RBAC, bitácora web, temas dinámicos y accesibilidad.
  3. En una fase institucional futura con DTIC-UAGRM, incorporar sincronización automática con Moodle 5.1 mediante Moodle REST Web Services o LTI 1.3.
